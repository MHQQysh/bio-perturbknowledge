# Agent 如何把 CRISPRi 论文变成可核验的数据

课程项目答辩 · 12 页 · 约 12 分钟。沿用新版封面插图、浅底和青绿色强调。任务书把 Agent、Tools、Skills 与数据表示设计放在同一个评价项，占 40%。开场就展示两个项目 Skill 的职责、输入和通过条件。实算结果放在后段，用来检验流程和记录设计。

**贯穿全场的问题**　给 Agent 一篇公开研究，它怎样判断某组细胞能否用于计算，又怎样让别人复现这个判断？

| 模块 | 作用 | 实际产物与验证 |
|---|---|---|
| Agent | 检索研究、提取证据、选择工具，遇到缺失时补证或保留状态 | 候选台账、研究级报告、演示日志 |
| verify-perturbation | 规定记录进入分析前需要哪些证据，哪些问题需要补证 | 读取验证、证据索引、对应记录指纹 |
| prepare-response | 规定哪些比较可算、如何处理计数、哪些字段可进入模型 Input | 响应与模型产物及运行日志 |
| 自定义工具 | 按记录读取实际细胞、运行检查、计算并导出 | 可执行脚本、真实退出状态、CSV 与 NPZ |
| Schema | 把各步骤交换的信息写成带来源的记录 | 13 条记录、字段定义与读入接口 |

## 01｜两项 Skill 让 Agent 的判断可核验

**上屏**　从公开论文到可计算的扰动记录。两项项目 Skill 分别约束记录核验和响应构建。

**版式与讲稿**　封面主图在右，左侧放标题与两个 Skill 的中文职责。开场用“对照身份不明时，Agent 应该继续算吗”引出项目。汇报制作所用的两个 Skill 不列为项目实现。

**页底**　课程任务书 II.2(2)、III；项目 `skills/`。

## 02｜论文到模型数据之间有两次判断

**上屏**　来源分散在论文、标签表与矩阵。第一次判断回答“哪些细胞和对照有证据”，第二次判断回答“这组数据允许怎样计算和使用”。

**版式与讲稿**　三份输入汇入一条记录，中间两道互相衔接的判断。以单细胞研究作为场景，不展开一般生物学背景。

**页底**　课程任务书 I.2–4；项目 `data/response_schema.json`。

## 03｜Agent、Skill 和工具各自做什么

**上屏**　Agent 检索并组织提取，按 Skill 选择检查；脚本执行读取联接、验证、计算和导出。补证后可重跑受影响记录。AnnData、SciPy 和 GEO 分别提供现成的矩阵结构、数值能力和数据入口。

**版式与讲稿**　上层 Agent 调度，下层用箭头连出材料→结构化记录→真实读取→响应与模型接口。两个 Skill 分别标在它们约束的决策点。说明脚本已执行的范围和分工。

**页底**　项目 `DELIVERY.txt`、`reports/workflow_audit.json`。

## 04｜Skill ① 核验一个扰动记录

**上屏**　`verify-perturbation` 输入研究提取、记录和矩阵来源。要求证据可定位、细胞存在且唯一、两组互斥、标签和数量一致、可用批次信息支持对照。异常保留状态与原因。

**版式与讲稿**　主图三段：输入证据 → `read_record.py` / `verify_records.py` → 有指纹的核验结果；另画补证回路。补充 `audit_workflow.py` 核对 schema 与已登记的结果指纹。展示一次真实读取时从哪里看到这些检查。

**页底**　项目 `skills/verify-perturbation/SKILL.md`、`data/reader_validation.json`。

## 05｜对照身份不明时，记录如何处理

**上屏**　Adamson 初轮缺少对照身份依据。公开二次整理代码提供映射，补证后重新读取 645 个 SPI1 扰动细胞与 1,655 个对照细胞。Dräger 仍缺关键映射，保留待核对。

**版式与讲稿**　左侧案例展示“发现缺口 → 定位证据 → 重新读矩阵”，右侧展示未恢复案例。Adamson 的依据来自二次整理，原始 guide 序列尚未全面独立复核。

**页底**　项目 `reports/supplement.json`、`reports/supplement_validation.json`、`data/project.json`；论文题名与 DOI 以对应研究条目核对后落版。

## 06｜Skill ② 把核验记录变成可用响应

**上屏**　`prepare-response` 确认计数尺度与对照，保留原始 counts，分析副本计算响应，导出 Input 白名单。尺度不明的记录保留源值。缺少独立重复时只报告描述性结果。

**版式与讲稿**　左边画检查和异常出口，右边画 `analyze_responses.py` 与 `export_model.py` 的实际文件输出。以 Replogle 的尺度未确认说明 Skill 如何改变选择；日志证明 Jost 分析与导出实际运行。

**页底**　项目 `skills/prepare-response/SKILL.md`、`reports/response_execution.json`。

## 07｜一条记录如何连接证据、细胞和模型字段

**上屏**　用 `jost2020_g1_1` 展示 context、perturbation、contrast、matrix、provenance 如何共同定位比较。实际读取 173 个扰动细胞与 779 个对照，矩阵为 952 × 33,694。

**版式与讲稿**　一条真实记录分成条件、细胞组、矩阵与文献来源，右侧用真实尺寸和字段说明。指出组均值的计算依据来自哪两个细胞集合。

**页底**　Jost 等，*Titrating gene expression using libraries of systematically attenuated CRISPR guide RNAs* · DOI 10.1038/s41587-019-0387-5；项目 `reports/demo_execution.json`。

## 08｜我们验证了哪些记录

**上屏**　33 项候选，11 项提取，10 项完成所选条件联接，形成 13 条比较记录。证据索引存有 91 项定位。候选根据原始研究、CRISPRi、单细胞 RNA 和公开入口初筛，后续另做实际联接检查。

**版式与讲稿**　研究与条件分栏计数。说明提取和联接的区别、演示子集的范围。答辩备用记录选 Jost、Adamson 和一条 Doctor 已核验条件，分别准备来源、对照和矩阵证据。

**页底**　项目 `data/project.json`、`reports/evidence_index.json`、`reports/workflow_audit.json`。

## 09｜同一批次三个条件能复现目标表达下降

**上屏**　共享 779 个 NTC 细胞的三个条件中，目标基因平均 CP10K 下降 80.8%、77.6%、87.9%。

**版式与讲稿**　大幅水平条形图，据 `target_effects.csv` 重绘，横轴 0–100%。简述这张图使用 CP10K 相对变化；模型 Target 使用 log1p CP10K 均值差。三条结果为描述性比较。

**页底**　Jost 论文题名与 DOI 10.1038/s41587-019-0387-5；项目独立计算。

## 10｜两项比较检验了不同的设计选择

**上屏**　对照选择：3 × 10 次实际重算，三个目标方向一致，向量相关范围随条件变化。记录表示：完整上下文保留 12/12 个定义字段，仅目标基因保留 1/12。

**版式与讲稿**　左侧为相关范围图，标明 r 与最小至最大值；右侧用两行呈现字段覆盖，注明两个版本均留有来源记录，字段覆盖是本项目定义的指标。已经完成的比较还无法估计启用 Skill 对准确率的独立贡献。

**页底**　Jost 论文题名与 DOI 10.1038/s41587-019-0387-5；`control_sensitivity.csv`、`representation_comparison.csv`。

## 11｜演示中让老师现场回查一条记录

**上屏**　启动候选检索 → 打开已有提取和证据位置 → 读取实际细胞 → 核对响应与 Input / Target。

**版式与讲稿**　将屏幕留给报告和执行结果。现有 `run_demo.py` 可重新检索候选并复用已核验记录计算。课堂演示还需补录或现场展示“指定候选→形成结构化记录→核验”这一段，以对应任务书要求。准备本地日志作为网络失败时的备用证据。

**页底**　课程任务书 II.3；项目 `reports/demo_execution.json`、`DELIVERY.txt`。

## 12｜下一步直接验证 Skill 是否改善结果

**上屏**　用同一批候选和同样材料，对比直接提取与启用项目 Skill 后的提取。统一人工参考，评估来源定位正确率、目标与对照联接错误率，以及证据不足时的正确保留率。

**版式与讲稿**　同材料并排两臂，输出汇到人工复核。该实验属于下一步方案。当前可提交的系统证据是两项 Skill、工具日志、核验记录和模型接口。

**页底**　项目提出的评估方案；任务书 II.2(5)。
